# 手冊上限與萬年曆（RTC）

依使用者提供的三份本機手冊整理，2026-10-07 未發版更新。沒有變更版本或製作安裝包。

來源：`C:/Fatek/FBe進階篇/進階篇應用指令.pdf` 第 7-151～159 頁；`基本應用指令.pdf` 第 7-2、7-18～19、7-26 頁；`CH16_萬年曆（RTC）.pdf` 第 16-1～2 頁。

## 上限由手冊定義，不以樣本最大位址代替

| 運算元 | 手冊範圍 | 目前編碼支援 |
| --- | --- | --- |
| 一般 M | M0～M1911 | 已擴充；高位址按既有編碼延伸，未經 GUI 驗證 |
| 特殊 M | M1912～M2001 | 未開放，不能當普通 M 任意寫入 |
| S | S0～S999 | 尚未開放一般 S 接點／線圈 |
| T、C | 0～255 | 有編碼；執行模擬另有範圍限制 |
| HR | R0～R3839 | 支援 |
| IR | R3840～R3903 | 支援讀取，不允許作寫入目的地 |
| OR | R3904～R3967 | 尚未實作 |
| SR | R3968～R4167 | 一般編碼尚未實作；僅周邊指令有 R3999 精確樣本，RTC 暫存器仍未支援 |
| ROR | R5000～R8071 | 已擴充至共用直接暫存器編碼；R5111／R8000 有樣本錨點 |
| DR | 基本篇 D0～D3071；進階篇 D0～D4095 | 編碼支援到 D4095，實際容量依 CPU／手冊版本 |
| 整字群組 | WX/WY0～240、WM0～1896、WS0～984 | 目前仍限已有編碼的精確群組，不能把表格最大值當作編碼公式 |

進階篇浮點表只允許 HR、ROR、DR、K、XR 的指定組合，不能將 IR/SR 等套用到所有指令。FZCP 的 S 不接受常數；SU／SL 可以。D 目的地不能是常數。

共用 R/D 編碼已擴充 R5000～R8071、D0～D4095，移除舊 D3999 的人工上限；所有多 word 指令仍檢查完整跨度。R8071、D4095 可作單 word，但不能作雙 word 起點。範圍可用不代表特定 CPU 存在相同容量，也不代表 D/P／間接形式的編碼已實作。

手冊的 16-bit 有號值為 -32768～32767，32-bit 為 -2147483648～2147483647。現有整數算術 Sb 的非負常數格式只是編譯器已實作範圍；負值、常數 Sa、暫存器 Sb 等不是 PLC 不允許，而是尚缺相應編碼實作。

浮點數採 IEEE-754 binary32，手冊概述約 ±3.4×10^38；格式最大有限值為 ±3.4028234663852886×10^38。MCP 按 binary32 轉換，拒絕溢位及非有限值，不以範例常數作上限。

基本篇 Timer PV 為 0～32767，出廠 T0～49=0.01s、T50～199=0.1s、T200～255=1s，可由架構配置調整。此記錄不改使用者現有專案的 ms 輸入契約，不自行更改計時縮放。

## RTC 讀取

此章描述 FB-PLC MA/MC 附加 RTC，不因 MCP 檔頭名稱就宣稱所有 CPU 有相同 RTC。

| 暫存器 | 內容 | 範圍 |
| --- | --- | --- |
| R4128 | 秒 | 0～59 |
| R4129 | 分 | 0～59 |
| R4130 | 時 | 0～23 |
| R4131 | 日 | 1～31，仍需符合月份 |
| R4132 | 月 | 1～12 |
| R4133 | 年碼 | 0～99 |
| R4134 | 週碼 | 0～6 |
| R4135 | 高 byte=時，低 byte=分 | hour×256+minute |

例如 08:30 的 R4135 是 2078（0x081E），不是 830。手冊這兩頁未定義世紀與週碼 0 對應哪一天，不自行補成 20xx 或星期日。

M1952=0 時 RTC 計時，CPU 每次掃描自動讀回 R4128～R4135。平常依時間開關輸出只需讀取時間，不必反覆校時。可用 hour×60+minute 比較每天的起訖分鐘；一般區間採起點含、終點不含，跨午夜採「晚於起點 OR 早於終點」。不指定或擅增 X/Y。

## 設定與補正

1. M1954=1 表示 RTC 已安裝。這是狀態，不是要寫入的命令。
2. 先使 M1952=1，停止 RTC 計時／自動讀回，避免設定值被覆蓋。
3. 將合法的秒、分、時、日、月、年碼、週碼寫入 R4128～R4134；R4135 是組合讀取值。
4. M1952 由 1→0 時將設定寫入 RTC，恢復計時與讀回。
5. 檢查 M1955；若為 1，設定不合理且未執行。

M1953 由 0→1 時做 ±30 秒補正：秒值 0～29 清成 0；30～59 清成 0 並進位一分鐘。M1954、M1955 不作可寫目的地。

M→M 禁止規則仍適用：不能用 M1954 直接驅動 M1952，或用 M 自保持拼出校時流程。手冊操作說明不是豁免專案架構政策。

## MCP 使用

- `get_manual_reference()`：提供上述上限、版本差異、RTC 位址與操作順序。
- `inspect_rtc_snapshot(registers)`：檢查呼叫者提供的 R4128～R4134 數值，可附 R4135 比對時分組合；不連線、不讀寫 PLC。

快照範例：`{"R4128":59,"R4129":30,"R4130":8,"R4131":7,"R4132":10,"R4133":26,"R4134":3,"R4135":2078}`。檢查會拒絕範圍錯誤、2 月 30 日、缺欄位／未知欄位；不宣稱已驗證世紀、週碼、RTC 硬體或原始 BCD 格式。

RTC `.ldr` 產檔尚缺 R4128～R4135 與 M1952～M1955 的特殊區編碼實作；這次完成手冊知識與快照檢查，沒有假造 RTC 控制檔，沒有 GUI／實體 PLC／RTC 執行模擬驗證。

## 模式查證與編碼界線

模式、D/P、單位與運算元上限先查使用者提供的手冊；`get_manual_reference` 的 `instruction_modes` 已整理 DIV48、MEAN、CRC16、PID、WDT、HSCT 的依據。手冊允許但序列化尚未實作的形式，應稱「尚未實作編碼」，不能稱為 PLC 不允許。

重新目視核對 PDF 原頁：7-3明列 DIV48 的 U/S=0有號、U/S=1無號，三個運算元各占3 words；此頁沒有 F474 的對照表，也未解釋 test17 FBn 單輸入形式的固定符號規則。7-11則確實將 CRC16 MD=1標為「保留」，MD=0才有明確的低位元組算法。這兩處差異保留精確依據，不因 GUI 能匯出就猜測執行語意。

其餘已查得的模式與合法上限依手冊說明；MEAN 常數 N、D/P 等形式可以是合法 PLC 用法，即使本 MCP 尚未有對應編碼。
